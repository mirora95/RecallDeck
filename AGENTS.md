# RecallDeck delivery rules

This repository is `mirora95/RecallDeck`. Before writes, pushes, comments or merges, verify authenticated account `mirora95`, remote, checkout path and repository owner/name. Work only in this repository for RecallDeck delivery; preserve all unrelated projects and checkouts.

Read CONTRIBUTING.md, the product design, the issue and current PR/review state first. Use an isolated checkout/worktree; preserve user checkouts. Branches start with an issue number. Follow the dependency order in issues and the current sprint; target two ready tasks per day, maximum three. Do not create empty work or lower verification standards to meet a quota.

Use small PRs, meaningful tests and relevant web/Android builds. Obtain an independent review before merge, accurately record its source, fix blocking findings and rerun affected verification. Match the exact tested and reviewed head commit during merge; all required CI checks/reviews must pass. No administrator bypass, force-push, branch-protection weakening, repository visibility changes or data deletion. Prefer a merge commit when allowed. Verify merge commit, mergedBy and issue/project status after merging.

Do not merge unrelated PRs. Do not publish to an app store, buy services, add cloud credentials or make a public hosted deployment without separate authorization. Public content must contain no private code, employer/client details, credentials or learner data.

Remove temporary validation photos/screenshots after checking and before sending/pushing, wherever stored. Never commit or push validation images. Keep results as text; preserve product assets and user-provided source images. Do not claim a device/emulator test was performed when only compilation or static review occurred.
